# Intent

How this application turns a near-miss, an ambiguous input, or a likely guess into help, and how it tells the person what it inferred.

## The idea

When input doesn't match exactly, or when the application could act on a prediction, the first question is "what did the person probably mean, or probably want?" Rejection, or silence, is the last resort.

## Rules

- **Disclose every inference.** If the system resolved or predicted something, it says so, so the person builds an accurate model of the application over time.
- **Ask when unsure.** A plausible but uncertain inference is offered as a question, answerable with minimal friction, not asserted as fact.
- **Say what's ambiguous.** When several interpretations are equally plausible, say so rather than picking one arbitrarily.
- **Record what was stated as stated.** What the person confirms becomes fact; what the system guessed stays labeled as a guess.
